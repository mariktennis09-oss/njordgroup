# Njord Group — сайт

Next.js 15+ (App Router), TypeScript (strict), Tailwind CSS v4.

## Запуск

```bash
npm install
cp .env.example .env.local   # опционально: аналитика, endpoint форм
npm run dev       # http://localhost:3000
npm run build     # продакшн-сборка
npm run start     # запуск собранного приложения (нужен Node-хостинг)
npx tsc --noEmit  # проверка типов
```

## Где менять контент

Весь текст и данные вынесены из компонентов в `src/content/*.ts` — компоненты
только рендерят структуру. Ничего не нужно искать по JSX-разметке:

| Файл | Что в нём |
|---|---|
| `content/company.ts` | Телефоны, офисы, счётчики статистики (`stats`) |
| `content/nav.ts` | Пункты меню, мегаменю, футер |
| `content/services.ts` | Тексты всех 7 страниц услуг (интро, чек-листы, шаги, FAQ) |
| `content/fleet.ts` | ТТХ судов |
| `content/routes.ts` | Список направлений на главной |
| `content/news.ts` | Новости (сейчас 3 заглушки) |
| `content/faq.ts` | Общие вопросы на странице «О компании» |
| `content/ports.ts` | Список портов для форм поиска рейсов |
| `content/seo.ts` | Название сайта, дефолтное описание, домен |

## Как обновить данные компании

- **Счётчики на главной (`StatsBand`)**: сейчас у всех статов `value: null` —
  секция не рендерится, пока значения не заполнены. Заказчик должен передать
  реальные цифры (лет в управлении флотом, рейсов в месяц, клиентов, тонн) —
  проставить их в `content/company.ts → stats`, секция появится автоматически.
- **Новости**: сейчас 3 демонстрационные записи в `content/news.ts`. Заменить
  на реальные или добавить свои по той же структуре (`NewsItem`).

## Где подключить реальные интеграции (сейчас работает на моках/демо)

1. **Отправка заявок** (`app/api/lead/route.ts`) — сейчас пишет заявку в

2. **Поиск рейсов** (`lib/api/voyages.ts`) — сейчас отдаёт демо-данные из
   `lib/mock/voyages.ts` (на странице `/search` и в виджете на главной честно
   показывается баннер «показаны демонстрационные данные»). Когда появится
   реальный API (портал `njord-portal.dev-seaportal.ru` или другой), заменить
   реализацию функции `searchVoyages` — сигнатура и место вызова менять не
   нужно.
3. **Отслеживание груза** — сейчас ведёт на внешний личный кабинет
   (`content/company.ts → portalUrl`), без имитации статусов. Если появится
   собственный API отслеживания — можно заменить редирект на
   встроенную страницу с таймлайном статусов.

## Переменные окружения

Все переменные необязательны — без них сайт работает, просто соответствующая
функция выключена. Шаблон — в `.env.example`, копировать в `.env.local`.

| Переменная | Зачем |
|---|---|
| `NEXT_PUBLIC_YANDEX_METRIKA_ID` | Номер счётчика Метрики. Пока пусто — на страницу не попадает ни байта аналитики. |
| `NEXT_PUBLIC_LEAD_ENDPOINT` | Куда форма шлёт заявку. По умолчанию свой `/api/lead`. |

## Хостинг

Все страницы генерируются статически (`generateStaticParams` для услуг,
флота и новостей), рантайм-SSR не используется. Единственный по-настоящему
серверный маршрут — `app/api/lead/route.ts`. Если сайт будет развёрнут на
обычном хостинге без Node (через `output: 'export'` в `next.config.ts`), этот
роут перестанет работать — форму нужно будет переключить на внешний endpoint
через `NEXT_PUBLIC_LEAD_ENDPOINT` (см. `lib/api/lead.ts`), а редиректы со
старых `.php`-адресов брать из `public/.htaccess` вместо `next.config.ts →
redirects()`.
